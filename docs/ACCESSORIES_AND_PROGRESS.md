# الأكسسوارات وسجل الإنجاز — ABDULMALIK ERP

## نطاق هذا التحديث

أضيفت وحدة مستقلة للأكسسوارات داخل تطبيق Flutter/Dart، على فرع `feature/accessories-module` المبني من `abdulmalik/development`.

### ما أُضيف في هذا التحديث

- عنصر تنقل مستقل باسم **الأكسسوارات** بجانب المخزون.
- شاشة الأكسسوارات تستخدم دورة حياة الأصناف الموجودة نفسها: إضافة، تعديل، أرشفة، بحث، باركود، سعر شراء وبيع، كمية، حد تنبيه، وحركة مخزون.
- تصنيفات جاهزة: أغطية وحافظات، سماعات، شواحن، كابلات، حماية الشاشة، حوامل، بطاقات ذاكرة، بطاريات وقطع، وأخرى.
- حفظ التصنيف داخل حقل `products.category` الحالي باستخدام بادئة داخلية `الأكسسوارات::`، دون إضافة عمود أو migration جديدة.
- فلترة من جهة الخادم باستخدام `section=accessories` و`section=general`، بحيث لا تظهر الأكسسوارات في قائمة المخزون العامة ولا تختلط معها.
- تبقى الأكسسوارات منتجات عادية من منظور الكاشير والمبيعات، وبالتالي يمكن بيعها عبر مسار البيع الحالي وتظل حركة المخزون موحدة.
- لا تتغير سجلات المنتجات القديمة؛ أي صنف لا يحمل البادئة يبقى ضمن المخزون العام.

## مكونات النظام الموجودة في قاعدة التطوير

وفق بنية الكود ووثيقة README في فرع التطوير، يتضمن المشروع أساساً وحدات لإدارة:
- استقبال أجهزة الصيانة ومتابعة مراحل الإصلاح والضمان وقطع الغيار.
- العملاء وسجل التعاملات.
- المنتجات والمخزون والباركود والأجهزة المسجلة بالـ IMEI.
- الكاشير والفواتير والمرتجعات والمدفوعات.
- المشتريات والموردين.
- الخزنة وحركاتها.
- المحافظ والخدمات.
- التقارير والمستخدمين والصلاحيات وسجل التدقيق.
- النسخ الاحتياطي والاستعادة.
- قاعدة SQLite محلية وخدمة HTTP للشبكة المحلية.
- بنية تطوير مستقبلية لتكامل Firebase، وهي غير مفعلة افتراضياً في إصدار Windows الحالي.

هذه قائمة بنطاقات موجودة في قاعدة المشروع؛ ولا تعني أن كل سيناريو تشغيلي قد اجتاز اختبار قبول ميدانياً.

## الحالة وخطوات التحقق المتبقية

هذا التحديث محفوظ على فرع مستقل ولا يدمج تلقائياً في `main` أو `abdulmalik/development`.

قبل اعتماد إصدار إنتاجي:
1. تشغيل `flutter analyze` داخل مجلد `source`.
2. تشغيل `flutter test` واختبارات التكامل ذات الصلة.
3. بناء Windows x64 وتشغيل المثبت على جهاز نظيف.
4. تجربة إضافة أكسسوار وتصنيفه وتعديله وأرشفته.
5. التأكد من عدم ظهور الأكسسوارات في المخزون العام، وظهورها في شاشة الأكسسوارات.
6. تجربة بيع أكسسوار من الكاشير والتحقق من خصم الكمية وحركة المخزون.
7. تجربة النسخ الاحتياطي والاستعادة على نسخة اختبارية.

## ملاحظة توافق البيانات

لم تُعدّل بنية جدول المنتجات ولم تُغيّر بيانات قاعدة البيانات القديمة. تستخدم الوحدة قيمة التصنيف الحالية، لذا لا تحتاج إلى migration. يجب الحفاظ على البادئة الداخلية عند أي استيراد أو تصدير أو تعديل مستقبلي للتصنيفات.
